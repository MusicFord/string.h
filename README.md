# s21_string+

> Собственная реализация библиотеки `string.h` на языке C с дополнительными функциями обработки строк.

Проект **s21_string+** — учебная реализация строковых и низкоуровневых операций стандартной библиотеки C. В рамках проекта отрабатываются работа с памятью, обработка C-строк, форматированный ввод и вывод, модульное тестирование и сборка статической библиотеки.

## Возможности

### Основные функции `string.h`

Реализуемые функции с префиксом `s21_`:

- `memchr`, `memcmp`, `memcpy`, `memset` — операции над участками памяти;
- `strncat`, `strchr`, `strncmp`, `strncpy`, `strcspn`, `strerror`, `strlen`, `strpbrk`, `strrchr`, `strstr`, `strtok` — копирование, сравнение, поиск и обработка строк.

Для `strerror` предусматриваются платформозависимые таблицы сообщений об ошибках для Linux и macOS, как требует техническое задание.

### Форматированный ввод и вывод

- `s21_sprintf` — частичная реализация форматированного вывода. По ТЗ поддерживаются спецификаторы `c`, `d`, `f`, `s`, `u`, `%`, флаги `-`, `+`, пробел, числовая ширина, числовая точность и модификаторы длины `h`, `l`.
- `s21_sscanf` — реализация форматированного ввода согласно требованиям соответствующей части технического задания.

### Дополнительные функции обработки строк

- `s21_to_upper` — копия строки в верхнем регистре;
- `s21_to_lower` — копия строки в нижнем регистре;
- `s21_insert` — вставка одной строки в другую с указанной позиции;
- `s21_trim` — удаление заданных символов в начале и конце строки.

### Общие элементы интерфейса

Заголовочный файл `s21_string.h` содержит публичные объявления функций, тип `s21_size` и макрос `S21_NULL`.

## Технологии и требования

- Язык: **C11**.
- Компилятор: **GCC**.
- Статическая библиотека: **`s21_string.a`**.
- Модульные тесты: **Check**.
- Стиль кода: **Google Style** для C/C++ в соответствии с техническим заданием.
- Ориентир по системным интерфейсам: **POSIX.1-2017**.
- Покрытие тестами: не менее **80% каждой функции**.

В реализации запрещено использовать стандартную `string.h` и другие библиотеки обработки строк. В тестах стандартные функции разрешены для сравнения поведения с оригинальной библиотекой.

## Сборка и запуск тестов

Перейдите в каталог с исходным кодом:

```bash
cd src
```

Собрать проект:

```bash
make all
```

Собрать статическую библиотеку:

```bash
make s21_string.a
```

Запустить модульные тесты:

```bash
make test
```

Сформировать HTML-отчёт покрытия:

```bash
make gcov_report
```

Удалить сгенерированные файлы:

```bash
make clean
```

Цели `all`, `clean`, `test`, `s21_string.a` и `gcov_report` предусмотрены техническим заданием. Для запуска тестов должны быть установлены Check и необходимые инструменты GCC/gcov.

## Использование библиотеки

Подключите публичный заголовок в своём C-файле:

```c
#include "s21_string.h"

int main(void) {
  const char text[] = "hello";
  s21_size length = s21_strlen(text);
  (void)length;
  return 0;
}
```

После сборки библиотеки пример можно скомпилировать, находясь в `src`:

```bash
gcc -std=c11 example.c s21_string.a -o example
./example
```

Перед компиляцией убедитесь, что `example.c` лежит в указанном каталоге либо поправьте путь к нему.

## Тестирование и покрытие

Тесты должны проверять обычные сценарии и граничные случаи. Для функций, поведение которых описано стандартной библиотекой, результаты реализации `s21_` сравниваются с соответствующими стандартными функциями.

Рекомендуется покрывать, в частности:

- пустые строки и нулевую длину;
- первый, последний и отсутствующий символ;
- граничные значения аргументов;
- корректность возвращаемых указателей и значений;
- поведение при разных флагах и спецификаторах форматирования;
- успешные и ошибочные сценарии, предусмотренные контрактом функции.

Команда `make gcov_report` должна формировать HTML-отчёт покрытия; целевое значение по ТЗ — **не менее 80% для каждой функции**.

## Правила разработки

1. Используйте префикс `s21_` для функций библиотеки.
2. Соблюдайте сигнатуры и поведение, предусмотренные техническим заданием и стандартом.
3. Не вызывайте стандартные функции обработки строк из реализации библиотеки; в тестах такое сравнение допускается.
4. Избегайте дублирования кода и придерживайтесь структурного программирования.
5. Перед отправкой изменений запускайте тесты и проверяйте сборку.
6. Не добавляйте в коммит объектные файлы, собранную библиотеку и сгенерированные отчёты, если правила репозитория не требуют иного.

## Командная работа

- Общий заголовочный файл `s21_string.h` согласуется командой до параллельной реализации функций.
- Каждый участник работает в своей ветке и отвечает за согласованные исходные файлы и тесты.
- Изменения вносятся в общую ветку через Merge Request.
- Перед слиянием проверяются сборка, тесты и отсутствие конфликтующих реализаций одних и тех же функций.
